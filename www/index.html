Quick actions

Tips toolbox — step by step

1 · Sign in from any device
  1. The password is shown by malstrom passwd (or printed by malstrom start).
  2. Change it anytime: sudo malstrom passwd <new>.
  3. Copy the LAN URL + password from Settings and open it on any device on the network — type the password to enter.
  4. The auth gate can be toggled under Settings → Operator access; it applies live without a restart.
2 · Load a target and arm your first WiFi attack
  1. Open Recon and hit SCAN FOR APs. USE a row, or press PULL FROM RECON on the Attack tab, to load the SSID, BSSID and channel.
  2. Pick a portal mode: Open (fake login) or WPA (evil twin). For WPA set a PSK or leave it blank to auto-generate; tick WPA2/WPA3 if the radio supports SAE.
  3. Set Deauth mode — Broadcast, Targeted (recon clients), Adaptive (low-noise) or Off — and WPA capture to handshake, PMKID or both.
  4. Fine-tune the twin with Clone BSSID, BSSID rotate, Hidden SSID, karma and shield toggles, and pick/preview/upload/clone a portal template.
  5. Press ARM ATTACK. The clone goes up, deauth fires and the portal starts serving — watch Monitor for connections and events.
3 · Catch credentials or handshakes
  1. Submitted portal passwords appear immediately under Loot → Credentials.
  2. Handshakes / PMKIDs land under Loot → Handshakes; verified captures auto-crack and the PSK shows under Loot → Cracked (wordlist is set in Settings).
  3. Keep Shield after capture on — clients that already handed over creds stop being deauthed.
  4. Unattended runs: press ARM AUTO HARVEST to scan, deauth, capture and rotate through WPA networks not already in the vault (it yields to manual attacks).
4 · Read the probe room and adapt the clone
  1. Monitor → Probe intelligence lists the SSIDs nearby devices are hunting for. Karma listen records them passively; Karma auto-respond even answers the probes.
  2. Press ADOPT on any interest to make that SSID the live clone target instantly.
  3. All probe requests are kept under Loot → Probes.
5 · Own a host and install your agent
  1. Get the victim onto your rogue AP — that is the point of the captive portal.
  2. In Recon run a host scan; the Rogue subnet quick-target locks onto the portal's own /24.
  3. In Sessions arm the Beacon, then copy the sh / ps1 payload and serve it from http://{{gateway}}/beacon (or /beacon.ps1).
  4. Run the agent on the host — it phones home and appears under Sessions. Rotating the agent key in Settings orphans old payloads; serve fresh ones afterwards.
6 · Command your fleet
  1. Pick a session and fire one-off commands from the console, or flip Terminal mode for a rolling per-session stream.
  2. The File browser walks remote directories — click to drill in and GRAB any file into Loot → Files (grabs are not capped like command output).
  3. Arm a reverse pivot like 8080-192.168.1.50:80 to reach deeper networks from the victim's position.
7 · Move laterally and dump credentials
  1. From a completed scan press SEND HOSTS → LATERAL to fill the target list (or type a CIDR / IPs yourself).
  2. Pick protocols (SMB / SSH / RDP / WinRM) and an attempt limit, then spray with harvested portal creds or a manual pair.
  3. Validated logins show under Owned hosts — run a SAM or LSA dump to pull NT hashes into the vault (hashcat -m 1000).
  4. Respect the limit — spray bursts trigger alerts.
8 · Poison, strip and crack
  1. With the chain armed (portal subnet up), hit ARM POISONING — Responder runs on the rogue interface.
  2. Missed DNS names hand over NetNTLMv2 challenges → Loot → Files as hashes.txt; smash CRACK HASHES to feed them to hashcat.
  3. The HTTP relay / SSL-strip toggle downgrades https links for victims already on the portal mid-attack.
  4. Disarm poisoning before cleanup to release the interface cleanly.
9 · Collect and export loot
  1. Loot groups everything: creds, devices, handshakes, cracked PSKs, probes, files.
  2. EXPORT CSV pulls the current tab; JSON dumps the creds. Download pcaps (22000), hashes and grabbed files directly.
  3. Pin anything so it survives CLEAR LOOT; each reset in Settings → Danger zone spells out exactly what it keeps.
10 · Watch, disarm and clean up
  1. Every post-exploitation engine (scan, spray, MITM, agents) is operator-armed only — it runs when you press the button, nothing more.
  2. The Alerts tab collects the red-flag events; watch the sidebar counter.
  3. DISARM stops the kill chain; FULL CLEANUP restores your original network config. Stop beacons from Sessions; the kill switch survives a reboot.
  4. Unshield a client from Monitor, or clear the whole whitelist, to serve the portal to that host again.
