# MALSTROM 2.4 — Capability and Engineering Gap Register

Status key: `open` = not started, `wip` = in progress, `done` = implemented + tested.

---

## 1. Tool self-hardening

| ID | Gap | Detail (source evidence) | Priority | Status |
|----|-----|--------------------------|----------|--------|
| H1 | Dashboard auth off by default, HTTP-only | `config.AUTH_REQUIRED` default `'0'`; token carried in URL fragment `http://…/#token=…` (`deploy/malstrom-cli:114`). No TLS, no CSRF/origin checks, no RBAC/multi-user. Now fixed: auth-off **forces** a loopback bind (never a public unauth dashboard), every response carries hardening headers (`X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy: no-referrer`, CSP `frame-ancestors 'none'`, `no-store`), a same-origin guard rejects cross-site requests when an Origin/Referer is present and mismatched (browser CSRF via img/form/fetch), and `MALSTROM_DASH_TLS=1` terminates the dashboard over a self-signed cert (same pattern as the TLS portal). Remaining: RBAC/multi-user intentionally out of scope (single-operator tool; the token gate + loopback/TLS cover the surface). | high | done |
| H2 | Loot stored plaintext / unencrypted at rest | Creds, hashes, passwords written as JSON + plaintext (`state.py` `CREDS_FILE`, `creds.log`); `EXFIL_ENABLED` reserved but nothing on-device protected. High-value cache on an on-site laptop. Now fixed: all sensitive stores are chmod 0600 via `state.harden_state()` (token/nonce/session/creds/beacon key/settings/state/audit/events), and `MALSTROM_VAULT=1` Fernet-encrypts the *mirrored* creds on disk (`creds.json.vault`/`creds.log.vault`; key in `~/.vault.key`, downloads auto-decrypt; requires python3-cryptography, else an ALERT and plaintext — never pseudo-crypto). | high | done |
| H3 | No evidence integrity / audit trail | Events trimmed to 2000 (`state.py:22-27`), no per-engagement archive, no hashing/TLS of evidence, no automated report generation. Operator actions not individually logged. Now fixed: append-only operator audit `state.audit()` (who/what/from-where, chmod 0600, never trimmed), wired through the dashboard dispatch for every mutating API action; per-engagement integrity snapshots `state.archive_engagement()` on disarm/cleanup/reset/reset-stock — every store copied into `state/engagements/<id>/` with a `.sha256` sidecar per file plus an index; archives live in the STATE dir so they survive `clear-loot`. Remaining: automated report generation out of scope. | medium | done |
| H4 | No out-of-band alerting | Legacy `config.sh` reserved `EXFIL_WEBHOOK`/`EXFIL_CHANNEL`; v2.4 has no webhook/email/notify path. Now fixed: `malstrom/notify.py` — `MALSTROM_EXFIL_WEBHOOK` (alias `MALSTROM_WEBHOOK`) POSTs every ALERT-class event (type/ts/msg, never loot unless `MALSTROM_NOTIFY_DETAIL=1`) to a bounded fire-and-forget queue; wired into `state.emit` via `add_alert_hook`, rate-limited, dead endpoints drop silently. | medium | done |

## 2. Capability gaps vs. comparable tools

| ID | Gap | Detail (source evidence) | Priority | Status |
|----|-----|--------------------------|----------|--------|
| C1 | Karma is passive-only (no auto-respond) | `karma.py:1-9` deliberately listens only; no PineAP-style probe-response / multi-SSID adoption. Now fixed: opt-in responder (`MALSTROM_KARMA_RESPOND`, dash toggle) that injects Probe Responses for the LIVE twin's identity only (broadcast + matching directed probes), rate-limited per station. | medium | done |
| C2 | Single-channel monitor, no multi-radio parallelism | deauth/capture/karma all steer one monitor vif to the target channel; single `active` state, one AP identity at a time; no channel hopping while armed; no scan-channel awareness. Now fixed: idle karma channel-hops the full band (all-channel client-interest map) and pins to the target channel when armed (deauth/capture coherence preserved); `MALSTROM_KARMA_HOP*` controls. | medium | done |
| C3 | No portal-page cloning | Only 7 static templates + 2 placeholders (`portal/templates/`); no scraping-of-real-login-page (Wifiphisher-style), no per-victim URL differences, no OTP/SMS field handling. Mostly fixed: `malstrom/clone.py` fetches the real page (https-first/http-fallback, 10s timeout, 2 MiB cap) and rewrites every asset to the portal's lazy on-disk `/__clone/<netloc>/<path>` gateway; password forms forced to the portal POST sink; per-victim 10-char `mvt` token (renderer + cred records); dashboard "clone a live login page" action creates + activates a custom template. Remaining: OTP/SMS field handling is intentionally out of scope (token field covers correlation). | medium | done |
| C4 | No real HTTP MITM / relay | Responder hashes only (`mitm.py`); no SSL-strip, no proxying victim traffic to the real site, no content interception, no ARP-spoof tunnel. Fixed (lite): `malstrom/relay.py` — the portal transparently relays victim cleartext HTTP upstream (the rogue AP is the gateway, so outbound :80 lands here) and rewrites every https:// reference to http:// so the victim never attempts TLS; safety rails reject the portal itself/gateway path/odd ports; request metadata (never content) mirrors to the vault (`web.log`); armed via `MALSTROM_RELAY` or the dash toggle, designed to be switched on after cred capture. | high | done |
| C5 | Beacon is minimal | `beacon.py`: plaintext HTTP, shared static key, no persistence/AV-evasion, no interactive shell, no SOCKS/pivot/port-forward through sessions, no Linux file-browser UI — only queue+cmd output. Fixed: interactive *terminal* mode (per-session rolling `term` buffer, separate from output history), Linux file browser (`@@LS::` tasks, GNU `ls -la` parsed into structured entries server-side + grab), and a reverse TCP port-forward pivot (`@@FW::lport-host:port` → socat/nc on the victim; validated, persistent-listed, delivered-once). Out of scope retained: SOCKS (use the port-forward + a tool), AV-evasion/persistence (an operator concern, not the beacon). | high | done |
| C6 | No WPA3/SAE relay or PMF bypass | Only WPA2→WPA3 "transition twin" (`services.py:69-74`); no downgrade/relay of genuine SAE commitments. | low | open |
| C7 | No beacon fidelity / evasion | hostapd conf is generic (`services.py:32-75`); doesn't replay the real AP's exact capa/rates/IE set; no MAC rotation or SSID cloaking mid-engagement; clone is fingerprintable. Now fixed: the recon pass captures the target's rate set (`supported_rates`/`basic_rates`), beacon interval, DTIM and HT40/Short-GI/STBC/LDPC/VHT/HE hints (`recon.fidelity_of`, latest-scan lookup `fidelity_for`), and `build_hostapd_conf` replays them sanitized (`MALSTROM_BEACON_FIDELITY`, on by default, hostile values clamped so a crafted beacon can never down the AP); mid-engagement evasion — `MALSTROM_BEACON_ROTATE` re-randomizes the decoy BSSID every N minutes while armed (decoy mode only; a cloned BSSID IS the identity and never rotates) and `MALSTROM_SSID_CLOAK` drops the twin's SSID broadcast (`ignore_broadcast_ssid=1`) — both as dashboard engagement toggles, driven by the engine loop. | medium | done |
| C8 | No client isolation on rogue net | `FORWARD` accepted globally (`services.py`); victims can reach each other and the operator LAN. Now fixed: hostapd `ap_isolate=1`, `-i ap -o ap` DROP, and portal→sibling-local-net DROPs; internet passthrough preserved. | high | done |

## 3. Portability / reliability

| ID | Gap | Detail (source evidence) | Priority | Status |
|----|-----|--------------------------|----------|--------|
| P1 | iptables-legacy only, no nftables, no IPv6 | Firewall code uses `iptables` binary exclusively (`services.py:330-391`, `linuxutil.py:523-524`); no `ip6tables`/`nft`; modern distros default nftables. Now fixed: backend detection (`linuxutil.fw_backend`, `MALSTROM_FIREWALL`=auto/i ptables/nft) with an atomic `nft -f` ruleset backend (`malstrom/firewall.py`, tables `ip malstrom` + `ip6 malstrom6`, whitelist-before-redirect order, isolation drops before accepts); arming is now REFUSED with an ALERT when no firewall tool exists at all; IPv6 guard (`MALSTROM_IPV6_GUARD`) drops v6 routed through the AP interface both directions (ip6tables or the ip6 table) and pins per-interface v6 forwarding to 0 for the engagement, restoring prior values at teardown. | high | done |
| P2 | Hard external deps gate whole engines | nmap/netexec/responder/hashcat/aircrack-ng are do-or-nothing for their engines; `--check` reports but cannot substitute. | medium | open |
| P3 | No sub-engine watchdog | Only daemon try/except + systemd `Restart=on-failure`; a hung monitor/beacon/scan worker thread has no health check. | low | open |

## Suggested implementation order

1. **C8** client isolation (small, self-contained, testable) — **DONE** (`ap_isolate=1` + FORWARD DROPs + teardown, `MALSTROM_CLIENT_ISOLATION` toggle)
2. **C1** optional karma auto-respond (opt-in, keeps the stealth promise) — **DONE** (radiotap Probe Resp injection, twin-only identities, per-station throttle, dash toggle)
3. **C2** single-radio scan-channel awareness — **DONE** (idle full-band karma hop, pinned-when-armed, `MALSTROM_KARMA_HOP`/`_DWELL`/`_CHANNELS`)
4. **C3** portal login-page cloning + per-victim tokens — **DONE** (clone engine + `/__clone` asset gateway + mvt token correlation + dashboard clone action)
5. **C4** HTTP relay/SSL-strip-lite over the rogue stack — **DONE** (portal transparent-cleartext-relay + https→http downgrade, self-loop/port guards, metadata loot, `MALSTROM_RELAY` + dash toggle)
6. **C5** beacon: interactive mode + SSH-ish pivot — **DONE** (terminal stream, structured file browser, reverse port-forward via socat/nc; SOCKS + AV-evasion/persistence explicitly out of scope)
7. **P1** nftables/IPv6 firewall layer — **DONE** (backend auto-detect iptables→nft, atomic `nft -f` policy, unconditional IPv6 drop-through-AP + v6-forwarding pin, arm refused when no backend)
8. **H1–H4** hardening pass — **DONE** (H1: security headers + same-origin/CSRF guard + loopback-when-auth-off + optional dash TLS; H2: 0600 lockdown + optional Fernet vault on mirrored creds; H3: append-only operator audit + per-engagement sha256 archives; H4: `MALSTROM_EXFIL_WEBHOOK` ALERT stream)
9. **C7** beacon fidelity + evasion — **DONE** (rate-set/beacon-meta/HT replay, decoy BSSID rotation on a timer, SSID cloak toggle; `MALSTROM_BEACON_FIDELITY`/`_ROTATE`/`_SSID_CLOAK`)
